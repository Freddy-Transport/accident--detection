# 未知完整视频事故自动发现报告

## 1. 目标与协议

本测试只验证无标注推理：

```text
完整未知视频 -> YOLO -> StrongSORT
-> 速度突降/异常停止/轨迹冲突/框重叠/队列增长规则
-> 候选片段 -> fine-tuned VideoMAE
-> 根据触发轨迹标注疑似事故车辆
```

推理阶段不读取 `accident_time`、事故区域或事故 actor。只有
`final_events.json` 写入后，独立评价脚本才加载标注进行时空评价。
YOLO/StrongSORT 只生成候选和车辆证据，最终事故语义判定由
`best_acc_top1_epoch_2.pth` 完成。红框是疑似事故车辆，不是框级真值。

## 2. 实现

- 轨迹规则改为逐帧带时间戳触发，支持 `speed_drop`、`abnormal_stop`、
  `trajectory_conflict`、`bbox_overlap`、`queue_growth`。
- 候选记录 `trigger_time_sec` 和 `primary_evidence_track_ids`。
- 相互重叠的 VideoMAE 阳性窗口合并为一个事件，避免同一事故重复报警。
- 可视化逐帧绘制绿色跟踪框，并将最终事件的主要触发轨迹改为红色疑似事故框。
- 评价脚本拒绝处理未声明 `annotation_free_inference=true` 或
  `annotation_inputs` 非空的推理结果。

## 4. 测试结果

| 指标 | 真实 CCTV | CARLA 虚拟 |
| --- | ---: | ---: |
| 完整视频帧数 | 450 | 181 |
| FPS | 14.98 | 20.00 |
| 轨迹规则候选数 | 4 | 2 |
| 去重后事故事件数 | 1 | 1 |
| VideoMAE 事故分数 | 0.841831 | 0.637852 |
| 自动发现时刻 | 4.473 s | 1.950 s |
| 事后读取事故真值 | 5.083 s | 5.550 s |
| 时刻绝对误差 | 0.610 s | 3.600 s |
| 主要疑似轨迹 | 3、8 | 2、3 |

| 最佳 IoU | 0.784629（轨迹 8） | 无可评价框 |

### 4.1 真实 CCTV

系统从 29.96 秒完整视频自动生成候选。最终事件由
`speed_drop + trajectory_conflict` 触发，VideoMAE 分数 0.841831。
发现时刻比事后真值提前 0.610 秒。轨迹 8 在事故时刻附近与官方事故区域
IoU 为 0.784629，本样本完成了自动时间与车辆空间定位。

### 4.2 CARLA 虚拟视频

两个候选的 VideoMAE 分数为 0.637852 和 0.581009，均超过阈值，
重叠窗口去重后输出一个事件。主事件在 1.950 秒触发，比真值提前
3.600 秒。主要轨迹 2、3 在事故时刻附近没有可评价框；YOLO/StrongSORT
仅提供轨迹 4，且未命中官方事故区域。因此该样本事故语义为阳性，
但事故车辆定位失败。

## 8. 结论

- 旧的使用 `accident_time` 生成候选的结果不再作为自动发现证据。
- 真实 CCTV demo 完成事故时间与疑似车辆定位。
- CARLA demo 事故语义为阳性，但时间误差较大且车辆定位失败。
- 两个样本参与了开发调试，不能作为无偏泛化指标。下一步应冻结规则和阈值，
  在未参与开发的完整 test 视频上统计事件召回、首报偏差、每视频误报数和
  事故车辆空间命中率。
- 不得用事故区域真值反向选择触发轨迹。
